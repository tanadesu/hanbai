# READ THE CROWD
会場の声を読んで、5分で売り切れ！

添付会場マップをそのまま使う、1人用のオフライン販売ゲームです。ビルド、外部API、ログイン、オンラインサーバーは不要です。

## 起動
`index.html` をブラウザで開きます。展示でランキングを安定して保持するには、同じブラウザ・同じURLで次のローカル起動を使ってください。

```sh
cd /Users/tanakakanadeyuu/hanbai
python3 -m http.server 4173 --bind 127.0.0.1
```

ブラウザで http://127.0.0.1:4173 を開いてください。これはPC内限定のサーバーです。インターネット接続は使いません。停止はターミナルで Ctrl+C。

## 遊び方
1. 「ゲーム開始」で5分の計測を開始。
2. マップの6か所から売り場を選び「ここへ移動」。到着後、3つのコメントを読む。A室とB室の間は直通できず、来場者と販売担当はロビー経由で移動します。
3. 商品・個数・価格方針を選んで販売。販売には4秒、移動には距離に応じて数秒かかります。

売れた分だけ在庫が減ります。利益は売上から売れた商品の仕入れ原価を引き、達成した目標の報酬を加えた金額です。売上と目標報酬は別々に表示します。閉場までに完了しない販売は計上しません。開始直後の在庫は計41個、補充はありません。移動中・販売中は操作をロックします。別タブや説明表示中も時間は進みます。

上位5記録を localStorage に保存します。プレイヤーの名前は収集せず、日時・販売個数・利益を記録。同点は先の記録を優先します。プライベートブラウズ、ブラウザデータ削除、異なるポート・URLでは記録が共有・保持されないことがあります。保存できない場合は結果画面に表示します。

## 調整する場所
- `data.js` / `CONFIG.products`：商品、初期在庫、仕入れ価格、基準価格、商品コメント。
- `data.js` / `CONFIG.places`：6売り場、画像上のパーセント座標、基本需要、場所の雑談。
- `data.js` / `CONFIG.phases`、`CONFIG.events`：時間帯、30〜60秒ごとのアナウンス、需要補正。需要の配列順は商品の順です。
- `data.js` / `CONFIG.goals`：毎回ランダムに提示する販売目標。商品・売り場・個数・期限・報酬を調整できます。報酬は各目標300円で固定し、毎回異なる目標でもボーナス上限を揃えています。重複した売り場の目標は同時に選ばれません。
- 目標報酬は売上とは分けて表示し、利益・最終ランキングには加算します。
- `data.js` / `CONFIG.policies`：価格・売れやすさの倍率。`duration` はプレイ秒数、`saleSeconds` は販売所要秒数。
- `engine.js`：移動時間、販売数の計算、集計。需要は内部だけで使用し、UIに表示しません。
- `app.js`：画面連携、タイマー、コメント更新、localStorage。
- `crowd.js`：空のマップ上を歩き、時間帯・イベントに合わせて行き先を変える来場者。
- `style.css`：PC・スマートフォンの配置、色、文字サイズ。
- `public/event-map-empty.png`：会場の建物・家具を保って人物と元の丸い案内アイコンを取り除いたマップ背景。元画像の縦横比を維持。
- `public/event-map.png`：ユーザー提供の原画像。

公平性のためイベント時刻は固定し、コメントと販売数に小さなランダム差を付けています。「早く売る」は基準価格の80%、「高く売る」は130%（10円単位に四捨五入）です。

## 確認
```sh
node --test tests/engine.test.js
```

ロジックテストに加え、Chromeで開始、移動、販売、操作ロック、在庫・利益計算、5分経過、結果、リスタート、再読み込み後のランキング、スマートフォン幅のはみ出しとホットスポット追従を検証しています。5分経過のブラウザ検証には仮想時計を使用しています。
