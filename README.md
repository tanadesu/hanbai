# READ THE CROWD
会場の声を読んで、5分で売り切れ！

添付会場マップを使う、1人用の販売ゲームです。通常のプレイとランキングはブラウザ内で動きます。ZERO ARCADEのユニコイン連携を使う場合は、このNodeサーバー経由で報酬APIへ接続します。

## ローカル起動

Node.js 22.9以降を用意し、プロジェクトフォルダーで実行します。

```sh
npm start
```

ブラウザで http://localhost:4173 を開きます。止めるときはターミナルで Ctrl+C を押します。HTMLを直接開いた場合やPythonの簡易サーバーではゲーム画面は表示できますが、報酬用APIルートは動きません。

ローカルでユニコイン連携も試すときは、`.env`（Gitには含まれない）をプロジェクト直下に作成し、運営から受け取った値を設定します。

```text
ZERO_ARCADE_API_URL=https://<admin本番ホスト>/api/arcade/rewards
ZERO_ARCADE_API_KEY=<このゲーム用の秘密キー>
```

実際のキーはチャット、コード、スクリーンショット、ログへ貼り付けないでください。値がない場合もゲーム本体は動き、結果画面に報酬連携のエラーと再試行案内が出ます。

## 遊び方

1. 「ゲーム開始」で5分の計測を開始。
2. マップの6か所から売り場を選び「ここへ移動」。到着後、3つのコメントを読む。A室とB室の間は直通できず、来場者と販売担当はロビー経由で移動します。
3. 商品・個数・価格方針を選んで販売。販売には4秒、移動には距離に応じて数秒かかります。

売れた分だけ在庫が減ります。利益は売上から売れた商品の仕入れ原価を引き、達成した目標の報酬を加えた金額です。売上と目標報酬は別々に表示します。閉場までに完了しない販売は計上しません。開始直後の在庫は計41個、補充はありません。移動中・販売中は操作をロックします。別タブや説明表示中も時間は進みます。

上位5記録を localStorage に保存します。プレイヤー名は収集せず、日時・販売個数・利益を記録します。同点は先の記録を優先します。プライベートブラウズ、ブラウザデータ削除、異なるポート・URLでは記録が共有・保持されないことがあります。保存できない場合は結果画面に表示します。BGMはタイトル画面で5曲から選べ、ゲーム中は右上でオン・オフできます。効果音も個別に切り替えられ、両方とも初期状態はオンです。

## ユニコイン連携

開始時にサーバーがプレイセッションIDを作ります。終了時は `Math.max(0, Math.floor(game.summary().profit))` を `points` として同じオリジンの `/api/reward` に送り、サーバーから運営の `ZERO_ARCADE_API_URL` へ `{playId, points}` をPOSTします。ユニコイン枚数への換算は運営API側が行います。ブラウザから運営APIへ直接送信せず、秘密キーもブラウザには渡しません。

同じセッションの再試行は同じ `playId` と確定済みスコアを使い、別スコアへの差し替えを拒否します。成功すると結果画面にAPI応答の枚数・QR画像・期限が表示されます。QRは受け取った画像データをそのまま表示し、URLへ変換しません。0枚の場合はQRを表示しません。通信エラーがあっても、利益・販売結果・ローカルランキングは表示されます。

利益計算自体は現在もブラウザ内です。サーバー中継とプレイ時間確認だけでは、ブラウザから偽の高得点を送る不正を完全には防げません。公開Webで運用する場合は、販売計算をサーバー側に移すかスタッフ確認を組み合わせてください。

## Vercel公開と秘密設定

このリポジトリにはVercel用の`vercel.json`と、同一オリジンで動く`api/session/start.js`・`api/reward.js`を追加しています。ゲーム画面は静的ファイルとして配信し、報酬処理はVercelのNode.js Functionsで動きます。ローカルでは`server.mjs`が同じAPIを提供します。`.openai/hosting.json`は別サービス用の静的配信設定で、Vercelの設定ではありません。

初回公開は、Vercel Dashboardで**Add New… → Project → Import Git Repository**から`tanadesu/hanbai`を選びます。Root Directoryはリポジトリ直下、Framework Presetは**Other**にします。Build CommandとOutput Directoryは上書きせず、Deployします。すでにこのリポジトリを接続したVercelプロジェクトがあれば、新しいプロジェクトを作らず、そのプロジェクトへデプロイしてください。GitHubの`main`への反映後は、Vercelが自動デプロイする設定が一般的です。

公開前に、対象Projectの**Settings → Environment Variables → Add New**で2つの環境変数を登録します。**Production**を選び、必要ならPreviewにも別途設定します。

- Key `ZERO_ARCADE_API_URL` / Value 運営から受け取った本番URL（`/api/arcade/rewards`まで含む）
- Key `ZERO_ARCADE_API_KEY` / Value このゲーム専用の秘密キー

値を設定したら保存し、**Deployments → 最新デプロイ → Redeploy**、またはGitHubの最新コミットをデプロイします。VercelはProject Settingsから環境変数を設定し、追加・変更後に再デプロイすると新しい値が有効になります。画面名は[Vercel公式の環境変数ガイド](https://vercel.com/docs/projects/environment-variables)で確認できます。

APIキーをブラウザ用JavaScript、HTML、GitHub、URL、公開環境変数へ入れないでください。キーの値をチャットやログに貼る必要はありません。キーが未設定でもゲーム結果は出ますが、ユニコイン連携は利用できません。

利益計算自体は現在もブラウザ内です。署名付きのプレイ開始IDとプレイ時間をサーバーで検証し、再試行には同じ`playId`を使います。スコアはブラウザから届くため、中継だけでは偽の高得点を完全には防げません。報酬APIが同じ`playId`への重複発行を防ぎますが、公開Webで運用する場合は販売計算をサーバー側に移すかスタッフ確認を組み合わせてください。

## 調整する場所

- `data.js` / `CONFIG.products`：商品、初期在庫、仕入れ価格、基準価格、商品コメント。
- `data.js` / `CONFIG.places`：6売り場、画像上のパーセント座標、基本需要、場所の雑談。
- `data.js` / `CONFIG.phases`、`CONFIG.events`：時間帯、イベント、需要補正。
- `data.js` / `CONFIG.goals`：毎回ランダムに提示する販売目標。
- `engine.js`：移動時間、販売数、利益などゲーム計算。
- `app.js`：画面連携、タイマー、ランキング、報酬セッションと結果表示。
- `server.mjs`：同一オリジンの静的配信と報酬中継、最低プレイ時間、再試行処理。
- `style.css`：PC・スマートフォンの配置と結果画面。
- `public/event-map-empty.png`：会場マップ背景。`public/bgm/`：5曲のBGM。

## 確認

```sh
npm test
```

ゲーム計算テストと報酬中継ロジックのテストを実行します。報酬テストは運営APIへ実際には接続せず、偽の応答で正常発行、0枚、早すぎる送信、スコア変更拒否、通信失敗後の同一内容再試行を確認します。
